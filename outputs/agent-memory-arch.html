Part B — 记忆是怎么产生和被用上的（全流程拆解）
①
用户说了一句话 用户

用户在第 3 次对话中说：

"我只坐早班飞机，经济舱就行，靠窗位置。 对了我一般从北京出发。"

这句话里藏着 4 条值得记住的信息，但也混着大量废话。

②
记忆系统：提取关键信息 记忆系统 LLM 辅助

记忆系统从对话中提取出结构化信息，过滤掉噪音：

// 提取结果 类别: 用户偏好 (Preferences) 摘要: "出行偏好：早班机、经济舱、靠窗、从北京出发" 详情: "用户明确表示只坐早班飞机，选择经济舱，偏好靠窗座位。常驻城市为北京，出发地默认北京。" 来源: 第 3 次对话
为什么需要"提取"而不是直接存对话？
原始对话有 500 tokens，提取后只有 60 tokens。节省 88% 存储空间，检索时更精准。
③
编码：把文字变成"坐标" CPU / 模型

为了以后能按意思查找（而不只是按关键词），需要把文本转成一组数字——向量：

// 原始文本 "出行偏好：早班机、经济舱、靠窗、从北京出发" // → 经过 Embedding 模型 → 变成 1536 维向量 向量: [0.023, -0.118, 0.045, 0.892, ..., -0.034]

意思相近的文字，向量也相近。以后用户说"订机票"，系统就能靠向量距离找到这条偏好。

④
存入数据库 数据库

一条记忆在数据库里长这样——文本、向量、标签存在一起，全部可检索：

┌─────────────────────────────────────────────────────────────┐ │ uri /user/alice/preferences/travel │ │ 摘要(L0) "出行偏好：早班、经济舱、靠窗、北京出发" │ │ 详情(L2) "用户明确表示只坐早班飞机……常驻城市北京" │ │ 向量 [0.023, -0.118, 0.045, ...] ← 按意思检索 │ │ 标签 type=偏好 user=alice ← 按条件过滤 │ │ 访问次数 0 ← 冷热判断依据 │ │ 更新时间 2026-05-01 14:30 ← 新鲜度依据 │ └─────────────────────────────────────────────────────────────┘
数据库在这一步做了什么？
❶ 检查有没有重复记忆（向量相似度 > 95% → 合并而不是新建）
❷ 对向量建索引（HNSW），以后能毫秒级搜到
❸ 写入即可检索，不用等批量刷新
⑤
一周后……用户回来了
"帮我订明天去上海的机票，老规矩。"

用户没说从哪出发、什么时间、什么舱位。如果没有记忆，Agent 只能追问。

⑥
数据库：精准召回记忆 数据库

记忆系统把用户的话转成向量，去数据库里搜：

// 查询 语义搜索: "订机票" 的向量 → 找最相关的记忆 条件过滤: user = alice AND type = 偏好 排序规则: 相关度 × 0.6 + 新鲜度 × 0.2 + 使用频率 × 0.2 // 返回结果（3ms） 命中 #1 "出行偏好：早班、经济舱、靠窗、北京出发" 相关度 0.94 命中 #2 "上次去上海住的全季酒店，觉得不错" 相关度 0.71
数据库在这一步做了什么？
❶ 在 alice 的记忆分区里搜索（分区索引，不扫别人的数据）
❷ 向量相似度 + 标签过滤同时执行（不是先搜再过滤）
❸ 多维度综合排序，把最有用的记忆排在最前面
❹ 自动更新访问次数 active_count += 1（热门记忆不会被淘汰）
⑦
组装上下文：只给 LLM 最有用的 记忆系统

从召回的记忆中挑选，在 Token 预算内组装最优上下文：

// 发给 LLM 的上下文（精简后仅 ~200 tokens） 用户偏好: 早班机 | 经济舱 | 靠窗 | 默认从北京出发 历史参考: 上次去上海住全季酒店，评价好 当前请求: "帮我订明天去上海的机票，老规矩"

对比：没有记忆时，需要用户花 5 轮对话、~4000 tokens 重复提供这些信息。

⑧
LLM 生成个性化回复 大模型
🤖 "已查询明天北京→上海的早班航班，经济舱靠窗： ① 7:00 CA1501 ¥680 ② 8:30 MU5101 ¥720 另外上次您住的全季酒店还有房，需要一起订吗？"

一句话搞定。不是因为 LLM 更聪明了，而是因为它拿到了正确的记忆。

Part C — 整个过程中，数据库提供了哪些基础能力

数据库 = 记忆系统的基础设施

📦
混合存储
文本、向量、标签存在同一行，不用跨系统拼装
→ 步骤④ 一条记忆 = 文本 + 向量 + 标签
🔎
混合检索
按意思搜 + 按条件过滤，在索引层一次完成
→ 步骤⑥ 语义搜索 + user=alice 同时执行
📊
多维排序
相关度 × 新鲜度 × 使用频率，综合打分
→ 步骤⑥ 三路加权排序，只返回最有用的
🔁
写入去重
新记忆与已有记忆太相似时，自动合并而非重复创建
→ 步骤④ 相似度 > 95% 就合并
🔥
冷热管理
常用记忆放快盘，长期不用的自动沉降到便宜存储
→ 步骤⑥ 命中后 active_count +1，热记忆不被淘汰
🏛️
租户隔离
每个用户/Agent 有独立的索引分区，互不干扰
→ 步骤⑥ 只在 alice 的分区搜，不碰别人
🛡️
安全防护
存储加密 · 访问审计 · 动态脱敏 · 写入校验
→ 敏感信息加密落盘，恶意内容写入时拦截
💰
成本优化
向量压缩 · 按需索引 · 批量处理 · 精度可调
→ 向量量化后存储降 4-33 倍，召回率几乎不变
