## 已确认的关键发现

### 1. WebSocket `sessions.compact` 可用
- `dangerouslyDisableDeviceAuth` 必须放在 `gateway.controlUi` 下（不是 `gateway` 顶层）
- 配置正确后，`openclaw-control-ui` client + admin scope 在容器内可连接

### 2. Compact timeout 问题
- GW 的 `DEFAULT_PHASE2_POLL_TIMEOUT_MS = 300_000`（5分钟）
- 大型 session 的 extraction 耗时 5-10 分钟，超出 GW 超时
- 现象：compact 返回 `commit_timeout`，但 OV extraction 在后台继续完成

### 3. Context 膨胀根因
- `eval.py` 的 `reset_session`（line 630-633）只重命名 JSONL 文件
- `sessions.json` 中 sessionId 不变，GW core 复用同一 session 内存 → 消息累积
- `commitTokenThreshold` 的 auto-commit 只清 OV pending tokens，不清 GW 会话消息
- WebSocket `sessions.compact` 才能同时处理 OV commit + GW session 清理

### 4. GW 模型确认
- 始终确认模型：检查 trajectory JSONL 中 `provider` 和 `modelId` 字段
- `docker restart` 命令对 GW 无效（GW 不是独立容器）

## 改进建议

### 1. 固定方案，停止改动

WebSocket `sessions.compact` 已验证可用，不应再切换。唯一待解决：compact 返回 `commit_timeout` 时（extraction >5min），增加异步等待逻辑。

参考实现：

```python
import json, time, requests, websocket

# ... trigger_compact() 同上（对齐 wmfact-eval-kit line 451-517）...

def compact_or_fallback(session_key, ov_url="http://127.0.0.1:1933"):
    """WebSocket compact，超时则 poll OV task API"""
    result = trigger_compact(session_key)
    if result.get("compacted"):
        return result

    # GW 超时，OV extraction 在后台继续 → 轮询 task API
    # 查找最近 OV session 的 task
    resp = requests.get(f"{ov_url}/api/v1/tasks", timeout=10)
    tasks = resp.json().get("result", [])
    for task in tasks:
        if task.get("status") == "pending":
            task_id = task.get("task_id")
            deadline = time.time() + 1200  # 20 min
            while time.time() < deadline:
                time.sleep(5)
                tr = requests.get(f"{ov_url}/api/v1/tasks/{task_id}", timeout=15)
                t = tr.json().get("result", {})
                if t.get("status") == "completed":
                    mem = t.get("result", {}).get("memories_extracted", {})
                    return {"compacted": True, "reason": "commit_completed_async",
                            "memories": mem.get("total", 0)}
                elif t.get("status") in ("failed", "cancelled"):
                    return {"compacted": False, "reason": t.get("status")}
    return {"compacted": False, "reason": "no_pending_task"}
```

### 6. Compact timeout 预期管理

| Session 规模 | 典型 extraction 时间 | Compact 结果 |
|-------------|-------------------|-------------|
| 单 session（<20 msg） | 30-60s | commit_completed |
| 累积 4-5 session | 2-5 min | commit_completed |
| 累积 8+ session | 5-10 min | commit_timeout → fallback poll |
| 累积 15+ session | 10-15 min | commit_timeout → fallback poll |

timeout 不是失败——extraction 在 OV 后台继续。fallback poll 确保提取完成后再进入下一 session。
